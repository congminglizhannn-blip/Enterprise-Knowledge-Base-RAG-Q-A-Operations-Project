## 现有字段映射与实施

| 任务概念 | 实际表 / 字段 | 实施方式 |
|---|---|---|
| 会话历史 | `chat_sessions` | 复用已有表，新增 `round_count` 和 `user_name_snapshot` |

## 数据与权限口径

- 超管可审计全量；部门管理员可审计本部门和子部门；普通用户仅查看本人历史，包括本人调岗前历史。
- 部门管理员传入其他组织/部门条件被覆盖为自身完整部门范围；普通用户传入组织/部门/他人用户条件被忽略。知识库筛选和用户筛选由后端验证。
- 部门管理员的用户选项包含范围内历史作者，保证人员调岗后仍可按作者审计原部门记录。组织/部门名称显示当前名称；组织/部门 ID 和用户姓名在会话中保留快照。
- 审计读取权限不等于代发或删除权限，不能在他人会话追加消息或删除他人会话。
- `round_count` 记录已保存回答数，包含现有生成链路保存的提示性回答；未提交的流式内容不计入。
- 新会话使用提问者的组织/部门，而非知识库归属。每个新会话固定一个知识库和一组组织/部门快照；切换知识库或调岗后继续问答建立新会话，避免覆盖历史。无需新增多知识库关联表。
- 保存使用 SQL 原子增量，消息、轮数和更新时间一起提交；仅修改消息/轮数不落另一半。
- 现有部门没有父子关系时均为根部门；不会自行猜测组织层级。超级管理员可通过部门创建/编辑 API 的 `parent_id` 建立真实关系。

## 迁移与历史限制

迁移：`20260924_0402_history_scope_filters.py`。已有单列组织、部门、用户、知识库索引保留；新增更新时间索引、部门/用户/知识库与更新时间复合索引、轮数与更新时间索引。

原代码曾将知识库组织/部门写入会话，并在切换知识库时覆盖归属。迁移只能按作者当前组织/部门回填，不能还原过往调岗时点或被覆盖的旧知识库。因此“保留产生时归属”从本次迁移之后的新会话开始可靠成立。迁移 downgrade 删除新增字段与索引，但不会把已修正的归属恢复为原错误归属。

本地迁移已应用，原有 12 条会话、58 条消息保留，轮数与数据库中的回答数量差异为 0。生产/其他环境需先执行：

```powershell
# 在 backend 目录执行
.\.venv\Scripts\python.exe -m alembic upgrade head
```

## 交互与接口

- 保留关键词大搜索框，300ms 防抖；组织、部门、知识库、用户、更新时间筛选自动查询，也可点击查询重试。
- 组织改变后清空部门选择，并向后端重新获取该组织的部门选项。
- 部门管理员的部门选择锁定为真实部门（含子部门），普通用户隐藏组织/部门/用户筛选。
- 更新时间和问答轮数表头切换升降序；筛选、排序和每页条数改变回到第 1 页；重置恢复更新时间倒序。
- 选项来自后端权限接口。请求取消和过期响应保护避免快速筛选时旧结果覆盖新结果。
- 空结果展示“暂无数据”，接口失败显示错误提示，不用空列表掩盖失败。

完整请求、响应和错误规则见 `api_reference.md`。
