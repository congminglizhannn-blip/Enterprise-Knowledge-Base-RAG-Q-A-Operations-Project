# 页面加载与认证恢复

本次保持 URL、页面布局样式和后端权限接口不变，业务路由移动到 `(business)` 路由组。

| 场景 | 行为 |
| --- | --- |
| 首次打开或刷新 | 根 AuthProvider 调用 /api/auth/me，显示恢复登录态 |
| 已登录侧栏导航 | 公共侧栏/顶栏保持挂载，内容区域显示页面加载骨架 |
| 知识库、入库、总览首次读数据 | 内容区域显示正在加载数据，不提前显示空统计 |
| 已登录时重试认证 | 保留页面，失败提示可重试；401 清空身份并跳转登录 |
| 退出或登录期间仍有旧认证请求 | AbortController 取消，版本号阻止旧结果覆盖 |

认证并发 retry 复用同一 Promise，超时 5 秒取消。Strict Mode 的效果清理会取消前次请求，可能在开发网络面板看到取消记录，不能算第二次恢复成功。

只缓存浏览器内 /api/kbs 和按知识库读取的文档列表，TTL 5 秒，最多 100 项，同时请求合并、各读取方独立消费 Response。写操作开始和结束、显式刷新、身份变更、401 时清空，旧请求不能重新填入缓存；认证和历史不缓存。其他设备的变更最多存在 5 秒列表延迟，后端操作和权限仍实时校验。文档明细仍由真实接口读取，保留解析完成统计口径，未用总文档数替代已解析数。

总览的会话请求与知识库/文档请求并行，失败分别提示。Next Link 保留框架生产预取行为；开发模式仍可能首次编译页面。

生产构建使用 `.next-production` 和 `tsconfig.build.json`，避免覆盖开发 `.next`。`npm run build` / `npm run start` 命令不变。配置变化后开发服务需要重新加载配置，若没有自动重启请手动重启前端。

验证：前端 node 测试覆盖认证状态转换、AuthGate 输出、并发缓存、过期、失败重试、身份切换期间旧请求完成；生产构建验证所有路由。尚未完成真实浏览器点击性能测量，不承诺具体毫秒降幅。

浏览器验收：登录后往返历史/知识库/入库，侧栏保持显示且无恢复登录态；硬刷新触发 /me；写入后返回列表可见新数据；注销再登录另一账号不显示前账号数据；慢网只出现内容加载；401 跳转登录。对比性能应使用生产服务，分别记录首次与重复导航的点击至内容完成时间及网络请求数。
